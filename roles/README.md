# 编写角色卡

每个角色对应 `roles/<角色名>.md`。在控制台「人格与角色」中创建、编辑和启用；管理员也可在 QQ 使用 `/role <角色名>`，用 `/role off` 清除。普通群友不能通过口头要求更改角色。

## 只写人设

写身份、语气、偏好、关系和对话示例。工具调用、分条、潜水、唤醒和记忆协议由预设负责，不重复写进角色卡，否则两代模式可能收到互相冲突的要求。

```markdown
# 角色名

## 身份
你是谁，别人怎样称呼你。

## 说话风格
句子长度、措辞和标点习惯。

## 反应与边界
面对不同话题时的态度，哪些事不参与。

## 对话示例
用几组短对话示范语气，不写工具调用。
```

## 按模式区分内容

确实需要区分时，在小节标题加 `〔一代〕` 或 `〔二代〕`：

```markdown
## 互动风格 〔一代〕
被问到时直接回答。

## 互动风格 〔二代〕
不熟悉的话题少插话。

## 常用语
这一节供两代共用。
```

标记只作用于当前标题到下一个标题之间的内容，不会按 Markdown 标题层级向子节继承。桥接先按模式筛选，再按 `role.maxInjectChars` 限制长度。以控制台的字符计数和警告为准，不把字符数直接换算成 token 或费用。

保存角色无需重启 DSH。二代会话通过角色提示词工具读取完整角色，刷新时机与限制见[二代预设](../dsh/agent-presets/qq-chat-v2/agent.cordis.yml)。角色卡不会改变工具权限。

模式标记和旧格式兼容规则以 [role-card.js](../src/role-card.js)及[对应测试](../scripts/test-role-card.mjs)为准；改这些行为后运行 `npm run test:role-card`。角色名由控制台校验，不使用路径或 `README` 作为名称。
