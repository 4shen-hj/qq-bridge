# 发布前隐私检查

每次提交公开内容前运行：

```sh
npm run privacy-scan
```

扫描器检查已跟踪文件和未被忽略的未跟踪文件的当前内容，不只检查暂存区，也不检查 Git 历史。命中值不会打印到报告中。

| 退出码 | 处理 |
| --- | --- |
| `0` | 扫描完整且没有命中，继续人工检查改动。 |
| `1` | 逐项确认命中，处理后重跑。 |
| `2` | 扫描不完整，先修复文件读取、规则或扫描限制问题。 |

二进制内容被跳过，启发式规则也可能漏报；扫描通过不代表不存在秘密。

## 处理命中

- 真实凭据或私有标识移出公开内容，示例使用脱敏数据。
- 本地配置、状态、音频和备份保留在忽略目录中。已跟踪文件不会因为新增 `.gitignore` 规则就自动移出版本控制。
- 确认是误报后，才在本地 `scripts/privacy-rules.json` 中添加精确的 `allowMatches`，同时指定文件、规则名和完整匹配值。不要整文件放行。

规则格式使用 [privacy-rules.example.json](../../scripts/privacy-rules.example.json)，实际匹配逻辑与默认规则见 [privacy-scan.mjs](../../scripts/privacy-scan.mjs)。本地规则可能包含私有标识，不提交该文件。

需要机器可读报告时运行 `node scripts/privacy-scan.mjs --json`。干净 CI checkout 可用 `node scripts/privacy-scan.mjs --tracked-only`。保留报告中的扫描完整性和跳过项，不把不完整扫描当作通过。

## 已经公开的数据

凭据一旦推送到公开仓库，先按泄露处理并撤销或轮换。删除工作区文件不能清除 Git 历史、缓存或他人的副本。历史重写需要单独协调，不能当作普通文档修复自动执行。

运行时的数据去向和权限边界见 [RULES.md](../../RULES.md)。
